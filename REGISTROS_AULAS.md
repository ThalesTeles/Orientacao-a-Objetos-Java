# Cronograma Replanejado (a partir de 07/10/2026)

**Diagnóstico.** Entre 09/09 e 30/09 o conteúdo do Módulo 4 se misturou: @Override e polimorfismo se estenderam por três encontros (Aulas 18–20) por causa dos problemas de ambiente, e o `static` foi apenas apresentado de forma panorâmica na Aula 20. Restam **11 encontros** (07/10 a 16/12) para o que antes estava previsto em 15.

**Estratégia de compressão.**
1. **Projeto como fio condutor:** o projeto prático é apresentado já na Aula 21 e cada módulo seguinte termina com uma tarefa extra-classe aplicando o conteúdo no projeto. Isso substitui as 4 aulas exclusivas de "Desenvolvimento Iterativo" do plano original.
2. **UML incorporada:** em vez de uma aula isolada, cada conceito novo (herança, classe abstrata, interface, composição) é desenhado no quadro em diagrama de classes no momento em que aparece. A aula de modelagem do projeto consolida.
3. **JUnit sem Maven:** os testes de unidade usam o suporte nativo do VS Code (Testing → *Enable Java Tests*, que baixa o JUnit para `lib/`). O Maven passa a ser conteúdo opcional — o ambiente já custou duas aulas, e introduzir uma ferramenta de build na reta final é risco alto para pouco ganho conceitual.
4. **Mesmo domínio em todo o Módulo 5 e 6:** o sistema `ContaBancaria` continua evoluindo (abstrata → interface → lista de contas → exceção de saldo → persistência em TXT), para que a aluna gaste energia no conceito novo e não em entender um domínio novo.

## TC44E - Aula 21 - Fechamento do Módulo 4: static e Apresentação do Projeto

Exercício de fechamento do polimorfismo: corrigir o saque de `ContaEspecial`, que hoje apenas simula o débito — introduzir um `setSaldo` `protected` na classe mãe e discutir por que ele não deve ser `public`. * Extra-classe: escolher o modelo de projeto e listar as entidades (substantivos) e ações (verbos) do sistema.

## TC44E - Aula 22 - Contratos e Abstração: Classes Abstratas
* Data: 14/10/2026
* Conteúdo: Por que `new ContaBancaria(...)` não deveria ser permitido se toda conta é corrente, poupança ou especial. Tornar `ContaBancaria` `abstract`, criar `ContaPoupanca` e um método abstrato (ex.: `calcularTarifaMensal()`), forçando cada filha a implementá-lo. Diagrama de classes no quadro (notação de classe/método abstrato em itálico).
* Extra-classe: identificar no projeto escolhido qual classe deveria ser abstrata.

## TC44E - Aula 23 - Contratos e Abstração: Interfaces
* Data: 21/10/2026
* Conteúdo: Contraste com o *duck typing* do Python: em Java, "se anda como pato" precisa estar escrito num contrato. Interface `Tributavel` implementada por `ContaEspecial` e por uma classe fora da hierarquia (ex.: `SeguroDeVida`), mostrando que interface não é herança. Diferença prática entre classe abstrata e interface (quando usar cada uma).
* Extra-classe: esboçar o diagrama de classes do projeto com pelo menos uma herança e uma interface.
